## 修复 Function 名称失配导致的静默失败（根因统一）

- 根因：Any 的注册 key（字符串拼接 PkgPath + Elem().Name() + Method().Name）与查找 key（runtime.FuncForPC 符号名）是两套独立命名体系，只要可能分叉就会失配
- 实测三种失配：绑定方法值 tk.Run → pkg.T.Run-fm；指针接收者 (*T).Run → pkg.(*T).Run（注册名因 Elem() 剥掉了 * 而不含括号）；嵌入提升 (&O{}).Run → pkg.Inner.Run-fm
- 实测确认：不同类型的同名方法不冲突（A.Run vs B.Run 为不同 key）；嵌入结构体用方法表达式反而正常（编译器生成 pkg.Outer.Run 转发包装，符号名用外层类型名）
- 修复：新增 checkFunctionName，在 functionName 中拦截 -fm 后缀 / 指针接收者 / 匿名函数三类不可注册写法，AddTask 阶段直接返回错误并给出修改建议，不再静默落库后每次执行失败
- 新增 warnUnregistered：函数名合法但尚未 AddTaskFunction 注册时打 warn（不阻断，支持先 AddTask 后注册的用法）
- 重构：AddTask/ResetTask 合并为 addOrReset(key, p, isReset)，消除两处重复的校验+落库+停表逻辑；顺手修掉 ResetTask 重建 timer 后 stopped 标记未复位的问题
- 测试：新增 TestFunctionNameMismatchRejected（4 类非法写法 + 断言不落库）、TestFunctionNameValidAccepted（值接收者/嵌入提升合法）；修正 TestFormatTimeAndFunctionName 对匿名函数的旧断言（改为应报错）
- 44 用例，gofmt/vet 无输出，go test -short -count=2 -race 全绿（5.594s）

## 未修改但建议后续优化（已向用户说明）

- 参数个数不足（len(Args) < NumIn）未校验，fv.Call 会 panic 再被 recoverTaskPanic 吞掉，任务反复失败但不终止
- 参数类型不匹配：argCasters 按形参 Name() 匹配，自定义类型（type MyInt int）与切片/结构体走不到的分支直接 ValueOf，类型不符即 panic
- Start() 之前调 AddTask 会永久阻塞：addRepeatingTimer 的 sendAction 在无消费者时卡在 s.do 上（文档要求先 Start，但无强制校验）
- 热路径 logrus.Info(fmt.Sprintf(...)) 每次执行至少 2 次字符串拼接 + 加锁写日志
- callFunction 每次执行都取 s.mu.RLock 读 Any，可用 atomic.Pointer 快照替代
- 落库函数名是全限定名，重构改包名/方法名后老任务重启即失效，建议显式别名注册

## 落实上轮建议的优化（不加 RegisterFunction）

- 参数校验前移：新增 buildInputs(fv, args) 统一校验个数（过多+过少）与类型（argCasters 之外的参数要求 AssignableTo；nil 仅允许赋给 isNilable 形参）；AddTask 时函数已注册则提前校验并报错不落库，执行期 callFunction 兜底复检（JSON 恢复的 Args 类型可能漂移），失败置 terminated 而非 panic
- 注意：基础类型形参（string/int 等）经 cast 宽松转换，nil 会转零值不报错，nil 校验仅对非基础类型生效（测试用自定义 struct 形参覆盖）
- Start 前死锁防护：Scheduler 增 started atomic.Bool，addOrReset 未启动直接报错（原实现会卡死在 sendAction）；错误文案按 replace 区分「添加/重置」

- 错误语义澄清：stop() 返回 false 时的文案区分「已触发或已暂停/已不存在」（RemoveTask/StopTask/addOrReset 更新分支）

- 测试：新增 TestAddTaskBeforeStartRejected（不阻塞+启动后可用）、TestArgMismatchRejectedAtAdd（4 非法 + 5 合法）、TestArgMismatchTerminatesAtRuntime（脏数据兜底）；48 用例，go test -short -count=2 -race 全绿（6.042s）
